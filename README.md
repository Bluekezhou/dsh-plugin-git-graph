# Git 提交图 · DSH

点击会话右上角分支按钮左侧的 **打开 Git 提交图** 图标（也可从右侧栏 **＋ → Git 提交图** 进入）。重复点击会回到当前会话已打开的提交图，不会新开一份。首次读取会话仓库最近的 200 条提交；点击 **加载更多** 追加下一批，每批最多 200 条，不限制总条数。读到本地历史末尾后不再请求。翻页期间如果 HEAD、分支等引用发生变化，刷新会从新的首批重新开始，避免把两次不同的历史拼在一起。

分支标签与提交标题排在同一行。文字紧跟该行最右侧的轨道，而不是整张图最宽的那一行：分支展开时文字向右移，轨道结束后可向左收回。如果右侧还有一条线经过，即使提交点在左边，文字也会让开那条线。点击提交标题（键盘可用 Enter 或空格）展开详情，查看完整哈希、父提交以及本次提交变更的文件。文件列表只在展开时读取，显示仓库相对路径和变更类型；重命名显示旧路径和新路径。「加载更多」追加的旧提交同样可以展开。普通提交与父提交对比，合并提交与第一父提交对比，初始提交与空树对比。空心点表示合并，短虚线表示父提交不在当前窗口。切换到其他仓库的会话，就能查看对应仓库。提交或更新分支后，可在视图内刷新。

有可折叠分支时，上方会出现「显示已合入的 N 个分支」。这里只统计能证明其独有提交的补丁均已进入当前 HEAD，且不被其他保留引用需要的分支；展开或收起会重新排图，不会操作 Git 分支。引用不全、浅克隆或比较预算不足时保留不能确认的提交，不猜测。

这是只读的历史视图，不创建 worktree，不切换分支，不修改文件，也不会从远端 fetch。图只反映本地已有的历史；尚未加载的父提交可在后续批次接续显示，浅克隆中本地不存在的父提交不会自动下载。

## 安装与验证

在 DSH 的 **插件 → 添加插件** 中选择独立的 `git-graph` 目录，不要选择同级的 `chat-reply-metrics`。需要 Host 上有 Git 2.45 或更新版本。适配并针对 DSH 0.2.2-rc.5 开发。

```sh
npm run check
git log --graph --date-order --oneline --decorate --all -200
```

第一条在本插件目录运行；第二条在目标仓库运行，可用来对照提交与分支关系。

## 设计参考

参考 pi-toolkit Web Hub 的 WorktreeGraph：按拓扑展示提交，标注 refs 和工作树；在 DSH 中支持逐批向前翻阅，而非固定长度的历史窗口。此插件使用 DSH 原生会话和界面扩展点，不依赖 pi-toolkit 服务或 Vue 运行时。
